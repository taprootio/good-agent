# GA0006 — Adopt good-agent in taproot and taproot-controls and remove the duplicates

## Scope

The work lands in the taproot and taproot-controls repositories; this task
tracks it from here.

- **taproot**: add the package GA0005 released (`good-agent`, or
  `@taprootio/good-agent` if the unscoped name was refused; the bin is
  `good-agent` either way) as an exact-pinned devDependency with the
  lockfile updated and installed in CI, then add `good-agent check` to
  `verify-changed.sh` as a `run_step` that receives the changed paths
  (design 6) and verify it from a clean checkout; fix `codex/size-budget` by
  moving the "Area-specific architecture" bullets into the `docs/architecture/`
  files they already link to; accept the per-file `claude/size` warning on
  `AGENTS.md` or set it to `info` in config, and record which; install the four shipped skills with `init --skill`;
  replace the loop sections of `docs/playbooks/work-task.md` with a pointer
  to good-agent's `work-task` and `review-loop` skills, keeping only Taproot
  policy (signed verification, computer use, creator surfaces, Postgres
  categories, `verify-changed.sh` ownership); replace
  `scripts/review-exchange/` with `good-agent review` once its self-test
  covers the exchange's cases, and retire the watcher; update
  `.claude/skills/work_task` to invoke the shipped skill.
- **taproot-controls**: merge `AI_GUIDELINES.md` (30,502 B) into the
  existing `AGENTS.md` (4,582 B) and move its reference sections (the ADR
  table, the visual-baseline and verification detail) into `docs/` with
  links, so the result stays under the 32,768 B Codex budget. Make `CLAUDE.md`
  `@AGENTS.md` plus any Claude-only notes; the import makes `claude/size`
  warn here too, so apply the same disposition as taproot (accept or set to
  `info`) and record which. Keep the Trellis block, add the same package
  as an exact-pinned devDependency with `bun.lock` updated (the repo
  installs with bun) and the guard to CI, install the skills with `init --skill`,
  and repoint its task-workflow instructions at the shipped `work-task` and
  `review-loop` skills while keeping Trellis's backlog lifecycle: today the
  loop pointers are the line inside the Trellis block of its AGENTS.md
  (which stays unedited) and the "Code reviewer instructions" section of
  `AI_GUIDELINES.md`; the repoint goes in the new GOOD-AGENT block, which
  states that it replaces the Trellis block's loop pointer for task work
  while the Trellis block's backlog steps still apply, and the merged
  reviewer instructions are dropped in favour of the review prompts.
- Both: add the `review` block to `good-agent.config.json` and the
  good-agent block to AGENTS.md (outside the Trellis block); the guard
  passes; the vocabulary in instruction files says "AI tool".
