# GA0002 — Ship the instruction-hygiene skill and `init --skill`

## Scope

- `skill/good-agent/SKILL.md` per [docs/design.md](../../docs/design.md)
  section 5.2: spec-only front matter (`name`, `description`, `license`,
  `metadata`), the six body sections in that order, under 200 lines, no
  Claude-only front matter keys. The audit section is the home of the
  contradiction check the guard cannot do; the proto `google.api.http`
  drift from Taproot is the worked example.
- Fix recipes keyed by rule id, generated from the same text `good-agent
  explain` prints, so the skill and the CLI never disagree.
- `good-agent init --skill` copies the skill to
  `.agents/skills/good-agent/SKILL.md` and `.claude/skills/good-agent/SKILL.md`,
  each prefixed with an HTML comment naming it as generated and giving the
  refresh command; refuses to overwrite a copy without that marker unless
  `--force`.
- The skill is listed in `package.json` `files` and validated in tests with
  the front-matter rules from the Agent Skills specification (name matches
  directory, lengths, allowed keys).
- README section "Install the skill" with the one command.

## Acceptance

- The reference validator's rules pass against `skill/good-agent/SKILL.md`
  (reimplemented in `test/skill.test.mjs`; the Python `skills-ref` tool is
  not a dependency).
- In a fixture repo, `init --skill` creates both copies, is idempotent, and
  `init --skill` after a hand edit without `--force` exits 2 with the reason.
- Claude Code lists the skill from `.claude/skills/` and Codex lists it from
  `.agents/skills/` in a manual check recorded in the closeout.

## Notes

- Skill, not playbook, for this content (design 5.1): it has to trigger on
  intent. It still reads as a playbook and a repo may link to it.
- `skills/copies-in-sync` (a rule that the two copies match) is v0.2 and not
  in scope here.

## Risks

- Claude Code "extends the standard"; any Claude-only key added later breaks
  the Codex and Copilot validators. The test guards the key set.
