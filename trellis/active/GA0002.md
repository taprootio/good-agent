# GA0002 — Ship the instruction-hygiene skill and `init --skill`

## Scope

- `skill/good-agent/SKILL.md` per [docs/design.md](../../docs/design.md)
  section 5.2: spec-only front matter (`name`, `description`, `license`,
  `metadata`), the six body sections in that order, under 200 lines, no
  Claude-only front matter keys. The audit section is the home of the
  contradiction check the guard cannot do; the proto `google.api.http`
  drift from Taproot is the worked example.
- Fix recipes keyed by rule id, written into `SKILL.md` between
  `<!-- BEGIN RECIPES -->` and `<!-- END RECIPES -->` by a committed script,
  `scripts/sync-skill.mjs`, from the rule modules' `rationale` and `fix`
  fields (GA0001). A test runs the script in check mode and fails on drift.
  No publish-time build step.
- `good-agent init --skill` copies every shipped skill directory (this one
  now; GA0003 adds three more), `SKILL.md` and its `references/` folder, to
  `.agents/skills/<name>/` and `.claude/skills/<name>/`. The copy keeps `---` as its first line;
  the first body line is an HTML comment naming it generated, giving the
  refresh command, and holding a hash of the whole file with only that
  marker line excluded, so front matter is covered too. A copy whose
  hash does not match its content was hand-edited: `init` refuses to
  overwrite it and exits 2 unless `--force`. A copy without the marker is
  treated the same way. Files under an installed `references/` folder have
  no front matter, so they are covered by a `.good-agent-manifest.json`
  written next to the installed `SKILL.md` that records each reference
  file's hash; a reference whose hash does not match was hand-edited and
  gets the same refusal without `--force`.
- The skill is listed in `package.json` `files`. GA0001's
  `test/skill.test.mjs` validates it; this story extends that test to the
  installed copies in a fixture so the marker placement is proven not to
  break the `---`-first rule.
- The README's existing "Five-minute setup" install lines and docs/design.md
  sections 4.2 and 5.3 updated in the same PR for `--force`, the copy
  locations and the hash marker, with `--config`, `--hook` and `--ci` marked
  v0.2 (unknown flags, exit 2, in v0.1); no second install section.

## Acceptance

- The reference validator's rules pass against `skill/good-agent/SKILL.md`
  (reimplemented in `test/skill.test.mjs`; the Python `skills-ref` tool is
  not a dependency).
- In a fixture repo, `init --skill` creates both copies, is idempotent, both
  copies pass the skill validator, and `init --skill` after a hand edit
  without `--force` exits 2 naming the edited copy, for an edit in the body,
  for an edit in the front matter alone, and for an edit in a reference
  file alone.
- Claude Code lists the skill from `.claude/skills/` and Codex lists it from
  `.agents/skills/` in a manual check recorded in the closeout.

## Notes

- Skill, not playbook, for this content (design 5.1): it has to trigger on
  intent. It still reads as a playbook and a repo may link to it.
- `skills/copies-in-sync` (a rule that the two copies match) is v0.2 and not
  in scope here.
- The recipe script is the one place skill text is derived from code; keep
  everything else in the skill hand-written.

## Risks

- Claude Code "extends the standard"; any Claude-only key added later breaks
  the Codex and Copilot validators. The test guards the key set.

## Refinements (2026-11-01)

- The marker line is `<!-- generated by good-agent init --skill; do not
  edit; refresh with: npx good-agent init --skill; sha256: <hex> -->` on
  the first body line; the hash covers the whole file with that line
  removed. `references/` files are hashed into `.good-agent-manifest.json`
  beside the installed `SKILL.md`.
- `scripts/sync-skill.mjs` rewrites the recipes between
  `<!-- BEGIN RECIPES -->` and `<!-- END RECIPES -->`; `--check` exits 1 on
  drift and is part of `npm test`.
