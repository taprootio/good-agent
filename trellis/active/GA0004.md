# GA0004 — Build `good-agent review`, the fresh read-only external reviewer

## Scope

Per [docs/design.md](../../docs/design.md) section 12, item 4 and "The
watcher question". Source: Taproot's `scripts/review-exchange/` in the
sibling checkout `../taproot` (private; commit `23496ea60`, 2026-10-30):
`watch.mjs`, `request.mjs`, `wait.mjs`, `exchange-lib.mjs`,
`findings.schema.json`, `review-prompt.txt`, `self-test.sh`,
`live-denial.sh`.

- Command: `good-agent review [--by codex|claude] [--author codex|claude]
  [--prompt diff|story|plan|design] [--base <ref>] [--task <path>]
  [--prior <findings.json>] [--verified "<command>"]... [--model <m>]
  [--effort <e>] [--timeout-minutes 45] [--no-wait] [--json]`. Without
  `--json` it prints a human summary (file, line, severity, suggestion per
  finding, then the count); with it, the bare findings array. `--by`
  defaults from `review.externalReviewer[--author]` in
  `good-agent.config.json`; with neither given, exit 2. `--prompt` defaults
  to `diff`; `diff` requires `--base`, `story` and `plan` require `--task`
  (`plan` reads the task file's `## Plan` section, which the `work-task`
  skill writes before asking; a task without one is exit 2), `design`
  requires `--task` and accepts `--base`. `--model` and `--effort` default from the per-tool
  `review` config, then the shipped defaults (Codex `medium` on the user's
  configured model; Claude `sonnet` at `high`).
- Runners: `codex exec` with `--sandbox read-only --ignore-rules
  -c approval_policy="never"`, hooks, plugins, apps and browser or computer
  features disabled, every MCP server Codex would load disabled by name and
  re-listed to confirm, `CODEX_API_KEY` and `OPENAI_API_KEY` stripped,
  `--output-schema` with the findings schema, `--output-last-message` to an
  attempt-numbered temp file; `claude -p` in safe mode with empty setting
  sources, hooks and plugins off, `--tools Read Grep Glob Bash` with
  `--allowedTools Read Grep Glob`, `--disallowedTools Edit Write NotebookEdit Agent`,
  `--permission-mode dontAsk`, `--json-schema`, API credentials stripped.
  Carry these over from Taproot's exchange verbatim where they still apply
  and verify each flag against the current CLI `--help` output.
- Prompt assembly from the GA0003 prompt files (`skill/review-loop/references/review-*.md`
  in the package) plus the runner ending (schema object, unwrapped to the
  bare array after validation) with the factual inputs:
  base and head shas, changed-file scope from `git diff --name-status` plus
  untracked files, the task path, prior findings, and what verification
  already passed (`--verified "<command>"`, repeatable).
- Tree digest (Taproot's status-plus-content digest) recorded before the
  reviewer starts and after it returns; a changed digest makes the result
  `REVIEW_UNSAFE` and exit 3.
- `schema/findings.json` is the wrapper object `{"findings": [item...]}`
  that `--output-schema` and `--json-schema` receive (structured output
  needs an object at the root); each item is `{file, line, severity,
  suggestion}` with severities `blocker|warning|nit`. The runner validates
  the object and every item, then unwraps it; the bare array is what the
  history file holds and what `--json` prints.
- Review history outside the tree: `~/.config/good-agent/reviews/<repo-slug>/<id>-<prompt>-rN.json`,
  `.meta.json` (runner, model, effort, shas, digests, timing, attempt),
  `.log`, with `<id>` derived as: from `--task`, the file's front-matter
  `id`, else its basename without extension; else from the branch name,
  the first `/`-separated segment matching `/^[A-Za-z]+[0-9]+$/`
  uppercased (`je/ga0004/slug` gives `GA0004`); else the branch name with
  `/` replaced by `-`; a detached HEAD without `--task` is exit 2.
  `<prompt>` is the prompt type and `N` the next free round for that id and
  prompt, so story, plan and diff rounds keep separate counters. A round is
  reserved by creating its `.meta.json` with the exclusive `wx` flag before
  the reviewer starts, so concurrent Codex and Claude reviews of one task
  never share a round; a collision retries with the next number. A round
  whose reviewer failed or whose tree moved keeps its number, records the
  failure in its `.meta.json`, and does not count toward the per-prompt
  cap. `<repo-slug>` is the basename of the git common directory's
  parent plus a short hash of its absolute path, so worktrees of one clone
  share a history. `GOOD_AGENT_REVIEWS` overrides the root.
- A per-reviewer lock at the reviews root (not per repo) so two reviews by
  the same reviewer never run at once, even across repositories; a second
  invocation waits, or
  fails fast with `--no-wait`. The lock records pid, host and start time; a
  lock whose pid is not alive on this host is taken over, and time spent
  waiting counts against `--timeout-minutes`.
- Exit codes: 0 clean (`[]`), 1 findings, 2 usage or config, 3 unsafe or
  reviewer failure (with `REVIEW_ERROR` detail and the log path).
- `--watch` is not in scope. A note in the README says how to run several
  lanes against one reviews directory (the lock serializes them).
- Self-test in `node --test` with fake `codex` and `claude` executables on
  `PATH`: happy path, schema violation, tree moved during review, reviewer
  exit non-zero, timeout kill, lock contention, stale-lock takeover, two
  reviewers reserving rounds for one task at once, stripped environment,
  and the MCP re-list refusal. No model call in CI.
- `scripts/live-denial.mjs`, an opt-in probe (never in CI) that uses the
  real login, asks each reviewer for a forbidden write in a private
  fixture, and checks denial plus an unchanged digest, as Taproot's
  `live-denial.sh` does.
- Rewrite the interim passage in `skill/review-loop/SKILL.md` (GA0003) to
  use `good-agent review`, keeping only a fallback for repos without
  good-agent installed; that fallback uses the prompt files in the skill's
  own `references/` folder, which `init --skill` installs with it.
- `docs/review-runner.md`: the command reference, the exit codes, the
  history layout, dated citations for every `codex exec` and `claude -p`
  flag the runner passes, and a table mapping each check in Taproot's
  exchange self-test (52 for Codex, 60 for Claude) plus the live denial
  probe to "covered by <test>" or "not applicable: watcher-only". GA0006
  retires the exchange only when no row is left blank. docs/design.md 4.6
  and 12 and the README are updated in the same PR, and section 9 (which
  already lists `src/review.mjs` and `schema/findings.json`) kept in sync.

## Acceptance

- From this repository, `good-agent review --by codex --prompt story --task
  trellis/active/GA0004.md --json` prints a findings array and leaves the
  tree digest unchanged; the same with `--by claude`.
- `review --by codex --prompt diff --base main` on a branch with a
  deliberate defect in a fixture returns at least one finding citing the
  right file and line; the same with `--by claude`.
- The self-test covers every failure mode listed above and runs in CI.

## Notes

- No watcher by default (design 12). The authoring tool runs this as a
  background command and gets one notification.
- Never an API key: the ChatGPT and Claude subscription logins are the only
  credentials, as in Taproot.
- `--by copilot` is later work; do not stub it.

## Risks

- CLI flags change between releases. Pin the minimum CLI versions in the
  runner, check `--version` at start, and fail with the exact flag that
  was rejected.
- A reviewer that returns prose instead of the schema. `--output-schema`
  and `--json-schema` make this rare; the validator makes it an error, never
  a silent pass.
