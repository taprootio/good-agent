# GA0005 — Claim the npm names and set up the release workflow

## Scope

- Try the unscoped name first: publish `good-agent@0.0.1` as a placeholder
  (README only, no bin) from the maintainer's login. npm support unpublished
  the previous `good-agent` in 2020 and may have blocked the name; the
  outcome decides the package name (design 1, "npm names", and open
  question 4).
- If accepted: `package.json` name `good-agent`, bin `good-agent`, with an
  `exports` entry `"./cli": "./src/cli.mjs"`. `@taprootio/good-agent` is
  published from `alias/package.json`, whose only dependency is
  `"good-agent": ">=0.1.0 <1"` (bumped to `^1` at 1.0; a plain `^0` would
  match the bin-less placeholder) and whose `good-agent` bin imports
  `main` from `good-agent/cli`, awaits `main(process.argv.slice(2))` and
  sets `process.exitCode` to the resolved code (the module never runs on
  import, GA0001). Order: release `0.1.0`; the owner
  publishes the alias once by hand (npm needs a package to exist before a
  trusted publisher can be set on it); configure the alias trusted
  publisher; then enable the second job in `release.yml`, which publishes
  the alias whenever `alias/package.json`'s version is not on the registry.
- If refused: `@taprootio/good-agent` is the package, bin `good-agent`, the
  owner hand-publishes a `0.0.1` placeholder of it (README only, no bin)
  before the trusted publisher is set, so `release.yml` still publishes
  `0.1.0` and creates the tag and Release on the bump merge; README and
  docs say so; no alias.
- `.github/workflows/release.yml` copied from Trellis: publish when
  `package.json`'s version on `main` is not on the registry, OIDC trusted
  publishing with provenance, tag and GitHub Release in the same job,
  prereleases to the `next` dist-tag. Two changes from the copy: the check
  job outputs `publish=false` and `release=false` when the version is
  `0.0.0`, so merging the workflow before the first bump publishes nothing
  (Trellis's copy would publish any version not yet on npm); and the gates
  the publish job runs are all four from this repo's AGENTS.md Loop
  contract (`npx @taprootio/trellis check`, `node --test`,
  `npm run typecheck`, `node scripts/good-agent.mjs check`), where
  Trellis's copy ran only its own backlog check.
  Trusted publisher configured on npm for `taprootio/good-agent` and
  `release.yml`.
- `CHANGELOG.md` with a `0.1.0` entry listing the nine rules and their doc
  citations, added to `files`; design 8 relies on it for rule and limit
  changes.
- `files` in `package.json` lists `scripts/`, `src/`, `skill/`, `schema/`,
  `README.md`, `CHANGELOG.md`, `LICENSE`. `LICENSE` is MIT, "Taproot IO, LLC".
- A dry run: `npm pack` contents reviewed in the PR and recorded in the
  closeout.
- Sequencing: `package.json` stays at `0.0.0` through GA0001 to GA0004 and
  this story's workflow PR, so merging `release.yml` publishes nothing. The
  trusted publisher for `good-agent` is configured before that merge. The
  last step is a PR that bumps the version to `0.1.0` and replaces the
  README's "design stage, nothing published" status line; the acceptance
  below is checked after that merge, which is the first release.

## Acceptance

- After the first real release, `npx good-agent@0.1.0 check` in an empty
  directory prints the `canonical/detect` finding and exits 1, and in a
  repo with `AGENTS.md` plus `CLAUDE.md` containing `@AGENTS.md` exits 0 (or
  the scoped equivalent if the name was refused). The alias, once
  published, passes the same two checks through `npx @taprootio/good-agent`.
- The push that merges `release.yml` at version `0.0.0` publishes nothing
  and creates no Release.
- The release workflow is a no-op on a push without a version bump.

## Notes

- Publishing is the owner's action. The task prepares everything and stops
  at the `npm publish` of the placeholder, which Jereme runs.

## Risks

- The placeholder squats the name with nothing useful behind it for a short
  while. Keep the gap short by scheduling it right before the v0.1 release.

## Refinements (2026-11-01)

- Everything up to the owner's `npm publish` of the placeholder is prepared
  on the branch; the story stays active until the owner has published and
  the first release has run, and the handoff names the exact commands.
