# GA0005 — Claim the npm names and set up the release workflow

## Scope

- Try the unscoped name first: publish `good-agent@0.0.1` as a placeholder
  (README only, no bin) from the maintainer's login. npm support unpublished
  the previous `good-agent` in 2020 and may have blocked the name; the
  outcome decides the package name (design 1, "npm names", and open
  question 4).
- If accepted: `package.json` name `good-agent`, bin `good-agent`;
  `@taprootio/good-agent` published from `alias/package.json`, a package
  whose only dependency is `good-agent` pinned to the same major and whose
  `good-agent` bin is a two-line script that imports `good-agent`'s CLI.
  Its first publish is manual by the owner; after that a second job in
  `release.yml` publishes it whenever `alias/package.json`'s version is not
  on the registry, so a major bump is a one-line edit. Both packages get a
  trusted publisher on npm for this repo and workflow.
- If refused: `@taprootio/good-agent` is the package, bin `good-agent`, and
  README and docs say so; no alias.
- `.github/workflows/release.yml` copied from Trellis: publish when
  `package.json`'s version on `main` is not on the registry, OIDC trusted
  publishing with provenance, tag and GitHub Release in the same job,
  prereleases to the `next` dist-tag. Trusted publisher configured on npm
  for `taprootio/good-agent` and `release.yml`.
- `files` in `package.json` lists `scripts/`, `src/`, `skill/`, `prompts/`,
  `schema/`, `README.md`, `LICENSE`. `LICENSE` is MIT, "Taproot IO, LLC".
- A dry run: `npm pack` contents reviewed in the PR and recorded in the
  closeout.
- Sequencing: `package.json` stays at `0.0.0` through GA0001 to GA0004 and
  this story's workflow PR, so merging `release.yml` publishes nothing. The
  trusted publishers are configured on npm before that merge. The last step
  is a PR that bumps the version to `0.1.0`; the acceptance below is
  checked after that merge, which is the first release.

## Acceptance

- After the first real release, `npx good-agent@0.1.0 check` in an empty
  directory prints the `canonical/detect` finding and exits 1, and in a
  repo with `AGENTS.md` plus `CLAUDE.md` containing `@AGENTS.md` exits 0 (or
  the scoped equivalent if the name was refused).
- The release workflow is a no-op on a push without a version bump.

## Notes

- Publishing is the owner's action. The task prepares everything and stops
  at the `npm publish` of the placeholder, which Jereme runs.

## Risks

- The placeholder squats the name with nothing useful behind it for a short
  while. Keep the gap short by scheduling it right before the v0.1 release.
