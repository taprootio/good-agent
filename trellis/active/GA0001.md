# GA0001 — Build the guard (`good-agent check`) v0.1

## Scope

Implement [docs/design.md](../../docs/design.md) sections 2, 3, 4, 7 and 9 for
the v0.1 scope in section 10.

- Package skeleton in the Trellis layout: `scripts/good-agent.mjs` (bin),
  `src/cli.mjs`, `src/config.mjs`, `src/discover.mjs`, `src/markdown.mjs`,
  `src/rules/<area>/<name>.mjs`, `src/report.mjs`, `schema/config.json`.
  Plain ESM with `// @ts-check` and JSDoc; `typescript` is the only
  devDependency, exact-pinned, for `npm run typecheck`. Zero runtime
  dependencies. `engines.node >= 22`.
- Discovery of instruction files per design 4.1 and canonical detection by
  inbound references per design 2, with the `canonical` config override.
- Rules, each in its own module exporting `{ id, severity, since, docs, run }`:
  `canonical/detect`, `canonical/name`, `codex/size-budget`,
  `claude/import-canonical`, `claude/import-depth`, `claude/size`,
  `links/broken`, `copilot/applyto`, `dry/copied-canonical`. Behaviour and
  default severities exactly as the design's rule table; every rule's `docs`
  array holds the URLs cited in design section 1.
- Parsing behaviour: code spans and fenced blocks blanked before link,
  import and reference parsing; generated blocks between
  `<!-- BEGIN X -->` and `<!-- END X -->` recognised; ignored directories per
  design 3 plus the `ignore` config globs.
- Commands `check`, `inspect`, `explain`, `rules` with the flags and exit
  codes in design 4.2 and 4.3. `check <path...>` exits 0 at once with
  "nothing to check" when no path is an instruction file or a link target of
  one.
- Human output in the four-part finding format of design 4.4; `--json` in the
  shape of design 4.5; `info` hidden unless `--verbose` or `--json`;
  `--strict` makes warnings fail.
- Config loading for `good-agent.config.json` per design 4.6, with
  `version: 1`, unknown rule ids and malformed files as exit 2.
- Tests with `node --test`: one `pass` and one `fail` fixture per rule under
  `test/fixtures/<rule>/<case>/` with `expected.json`; the extra cases design
  section 7 lists (nested Codex chain, override file, Markdown-link pointer,
  code-span `@` that must not count, no-CLAUDE.md both ways, wholesale copy
  without per-block noise); `test/cli.test.mjs` for exit codes, JSON shape,
  `--strict`, `--rule` and the fast exit; `test/discover.test.mjs` for the
  five detection layouts.
- `scripts/corpus.mjs` runs `check --json` against sibling checkouts of
  taproot, taproot-controls and www.jeremeevans.com when present and diffs
  against `test/corpus/*.expected.json`; skipped when absent.
- The README's example output is produced by a fixture and snapshot-tested
  so the article screenshot and the code agree.
- The repo passes its own guard: `npx good-agent check` on this repository
  exits 0, and `node --test` plus the guard are the `gates` in AGENTS.md.

## Acceptance

- `node scripts/good-agent.mjs check` on the three corpus repos reports what
  [docs/findings.md](../../docs/findings.md) records: exit 1 with
  `codex/size-budget` and `claude/size` on taproot; exit 1 with
  `claude/import-canonical` and `canonical/name` on taproot-controls; exit 0
  with no findings on www.jeremeevans.com.
- Every rule has `explain` text with rationale, fix and at least one doc URL.
- `npm test` and `npm run typecheck` pass with no dependencies installed
  beyond `typescript`.

## Notes

- Rule ids are public API from this task on (design 8). Rename before
  merging, not after.
- `init`, the skill and publishing are GA0002 and GA0005; do not fold them
  in.
- The prototype that produced the findings is not in the repo; design
  section 3 is the specification, and its noise controls are requirements.

## Risks

- Markdown parsing without a dependency: links inside tables, reference-style
  links and nested brackets. Keep the parser to what the design needs
  (inline links, `@` imports, flat front matter, fenced and inline code) and
  test the Taproot files' shapes.
- Node's `fs.glob` is still experimental in the 22 line; the walker is
  hand-written and must honour `ignore` consistently in discovery and in
  reference validation.
