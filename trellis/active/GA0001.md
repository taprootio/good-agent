# GA0001 — Build the guard (`good-agent check`) v0.1

## Scope

Implement [docs/design.md](../../docs/design.md) sections 2, 3, 4, 7 and 9 for
the v0.1 scope in section 10.

- Package skeleton in the Trellis layout (`npm test` runs `node --test`):
  `scripts/good-agent.mjs` (bin; it calls `main(argv)` from `src/cli.mjs`,
  which resolves to an exit code and never runs on import, and sets
  `process.exitCode`),
  `src/cli.mjs`, `src/config.mjs`, `src/discover.mjs`, `src/markdown.mjs`,
  `src/rules/<area>/<name>.mjs`, `src/report.mjs`, `schema/config.json`.
  Plain ESM with `// @ts-check` and JSDoc; `typescript` and `@types/node`
  are the only devDependencies, exact-pinned, for `npm run typecheck` over
  the shipped `.mjs` files. Zero runtime dependencies. `engines.node >= 22`.
  The CLI help and the README state that the guard checks the directory it
  runs in and that full Codex budget validation needs a run from the
  repository root (design 4.2).
- Discovery of instruction files per design 4.1 (no `GEMINI.md` in v0.1) and
  canonical detection by inbound references per design 2, with the
  `canonical` config override.
- Rules, each in its own module exporting
  `{ id, severity, since, docs, rationale, fix, run }` so `explain` and the
  skill's fix recipes (GA0002) read one source:
  `canonical/detect`, `canonical/name`, `codex/size-budget`,
  `claude/import-canonical`, `claude/import-depth`, `claude/size`,
  `links/broken`, `copilot/applyto`, `dry/copied-canonical`. Behaviour and
  default severities exactly as the design's rule table; every rule's `docs`
  array holds the URLs cited in design section 1 for its tool, primary page
  first; human output prints `docs[0]` on the `docs:` line and `--json`
  carries the whole array.
- Parsing behaviour: code spans and fenced blocks blanked before link,
  import and reference parsing; generated blocks between
  `<!-- BEGIN X -->` and `<!-- END X -->` recognised, excluded from `dry/*`
  counting, and any finding inside one annotated "generated by X; fix the
  generator", except the `GOOD-AGENT` block, which is hand-written in v0.1; ignored directories per design 3 plus the `ignore` config
  globs.
- Commands `check`, `inspect`, `explain`, `rules` with the flags and exit
  codes in design 4.2 and 4.3. `check <path...>` exits 0 at once with
  "nothing to check" when no path is an instruction file or a link target of
  one, where the config file in effect (default path or `--config`) counts
  as an instruction file so a config-only commit runs the full check.
  `inspect --json` has the shape design 4.5 gives.
- Human output in the four-part finding format of design 4.4; `--json` in the
  shape of design 4.5; `info` hidden unless `--verbose` or `--json`;
  `--strict` makes warnings fail.
- Config loading for `good-agent.config.json` per design 4.6, with
  `version: 1`, unknown rule ids and malformed files as exit 2. The schema
  and loader accept and validate the `review` block (the `externalReviewer`
  map and per-tool `model` and `effort`) even though only GA0004 reads it,
  so GA0003 adding that block never causes an exit 2. `externalReviewer`
  keys and values must be `codex` or `claude`; `model` and `effort` are
  validated as non-empty strings only, since the CLIs reject bad values.
- The repo root is `--cwd` or the current directory, never the git top
  level (design 4.2); `test/discover.test.mjs` includes a run from a
  subdirectory.
- A committed `good-agent.config.json` for this repository that ignores
  `test/fixtures/**` and `test/corpus/**`, so the deliberately broken
  fixture files never reach the self-check.
- `test/skill.test.mjs`: a validator for every `skill/*/SKILL.md` against
  the Agent Skills front-matter rules (`name` and `description` required,
  name matches directory, lowercase letters, digits and hyphens only, no
  leading, trailing or doubled hyphen, name and description lengths,
  allowed keys only, `---` on line 1). The front-matter
  parser in `src/markdown.mjs` handles indented continuation lines and a
  one-level nested `metadata` map (design 9), which the shipped skills use.
  GA0002 and GA0003 add skills; this story ships the test with no skills
  yet.
- `.github/workflows/test.yml` on Node 22: `node --test`, `npm run
  typecheck`, and `node scripts/good-agent.mjs check` on this repository.
- Tests with `node --test`: one `pass` and one `fail` fixture per rule under
  `test/fixtures/<rule>/<case>/` with `expected.json`; the extra cases design
  section 7 lists (nested Codex chain, override file, Markdown-link pointer,
  code-span `@` that must not count, no-CLAUDE.md both ways, wholesale copy
  without per-block noise, a `claude/size` launch set from an
  `AGENTS.md`-only repo and from a `.claude/CLAUDE.md`-only repo, the
  `claude/size` info case (two files under the target whose total is over
  it), a `@/absolute` import that must not count for canonical detection,
  an empty `AGENTS.override.md` beside an oversized `AGENTS.md` (the
  override wins the directory and contributes nothing, so there is no
  budget finding and `inspect --json` lists the override with zero bytes
  and the shadowed `AGENTS.md`), and a config-only changed-path case); `test/cli.test.mjs` for exit codes, JSON shape,
  `--strict`, `--rule`, the fast exit, and one case each for `inspect`,
  `explain` and `rules`; `test/discover.test.mjs` for the five detection
  layouts.
- `scripts/corpus.mjs` runs `check --json` against sibling checkouts of
  taproot, taproot-controls and www.jeremeevans.com when present and diffs
  against `test/corpus/*.expected.json`; skipped when absent. Each git
  sibling is evaluated at the commit its expected file records, extracted
  with `git archive <sha>` into a temp directory (read-only on the
  sibling); www.jeremeevans.com is skipped with a note when its `AGENTS.md`
  size differs from the pinned 13,455 bytes.
- The README's example output is produced by a fixture and snapshot-tested
  so the article screenshot and the code agree; the test replaces the
  version in the header and in JSON `version` with a fixed token before
  comparing, since `package.json` stays at `0.0.0` until release (GA0005).
- The README's pre-commit hook and GitHub Actions snippets (design 6) run
  against the built CLI in a fixture, including an empty commit and a
  staged path with a space for the hook, and are kept in sync with the
  README.
- The repo passes its own guard: `node scripts/good-agent.mjs check` on this
  repository exits 0, and the four `gates` already listed in AGENTS.md (the
  Trellis check, `node --test`, `npm run typecheck`, the guard) all stay
  green; none is removed.

## Acceptance

- `node scripts/good-agent.mjs check` on the three corpus repos, at the
  commits (and, for www.jeremeevans.com, the `AGENTS.md` size and date)
  that [docs/findings.md](../../docs/findings.md) pins, reports what it
  records: exit 1 with
  `codex/size-budget` and a per-file `claude/size` warning on `AGENTS.md`
  (590 lines via the import) and nothing else on taproot; exit 1 with
  `claude/import-canonical` and `canonical/name` on taproot-controls; exit 0
  with no findings of any severity, info included, on www.jeremeevans.com.
- Every rule has `explain` text with rationale, fix and at least one doc URL.
- `npm test` and `npm run typecheck` pass with no dependencies installed
  beyond `typescript`, `@types/node` and their lockfile-pinned transitive
  dependencies.

## Risks

- Markdown parsing without a dependency: links inside tables, reference-style
  links and nested brackets. Keep the parser to what the design needs
  (inline links, `@` imports, the front-matter subset of design 9 with
  continuation lines and one nested map, fenced and inline code) and test
  the Taproot files' shapes.
- Node's `fs.glob` is still experimental in the 22 line; the walker is
  hand-written and must honour `ignore` consistently in discovery and in
  reference validation.
