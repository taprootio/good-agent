# GA0009 — Show why a reviewer failed in `good-agent review`

## Scope

Defect found adopting 0.1.0 in taproot. Codex refused the configured model
(the owner's `~/.codex/config.toml` set one that the ChatGPT login does not
accept). The runner printed only `REVIEW_ERROR: codex exited 1`. The cause
was in the round's `.log`:

```
ERROR: {"type":"error","status":400,"error":{"type":"invalid_request_error","message":"The 'gpt-6.1-sol' model is not supported when using Codex with a ChatGPT account.","code":"model_not_found"}}
```

The fix is in `src/review.mjs`, in the `review` function, where the failure
message is built for `result.status !== 0`.

- On a non-zero exit, print to standard error, after the existing
  `REVIEW_ERROR` line:
  - the cause: the reviewer's output lines that contain `error` (case
    insensitive), the last ten of them; when none do, the last twenty lines
    of its standard error, or of its standard output when standard error is
    empty. Each line is cut at 600 characters (a Claude envelope is one long
    line), and blank lines are dropped;
  - the model and effort passed, or, when no model was passed, a line
    saying so and naming the source of the default: `~/.codex/config.toml`
    for Codex, the CLI's own default for Claude (the runner passes
    `--setting-sources ""`, so Claude's settings files are not read). When a
    model was passed, say whether it came from `--model` or from
    `review.<tool>.model` in `good-agent.config.json`;
  - when the output contains `model_not_found`, one hint line: set
    `review.codex.model` (or `review.claude.model`) in
    `good-agent.config.json`, or pass `--model`.
  The round's `.log` path is already in the `REVIEW_ERROR` line and stays
  there.
- The existing rejected-flag note stays in the `REVIEW_ERROR` line.
  `.meta.json`'s `error` stays the one-line message; the detail lines are
  printed, not stored (the `.log` already holds the full output).
- `.meta.json` already records `model` (null when none was passed) and
  `effort`. Add `model_source` (`"flag"`, `"config"` or `null`) so a round
  that used the reviewer's own default says so.
- `docs/review-runner.md` and `docs/design.md` (section 12) describe the
  output and the new meta field in the same change.
- Nothing in the suite calls a real Codex or Claude; the tests use the fake
  executables in `test/fakes/`.

Not in scope: changing which model is used, retrying with another model,
or classifying other failure causes (authentication, quota).

## Acceptance

- With a fake Codex that prints the `model_not_found` ERROR line above to
  standard error and exits 1: exit 3, and standard error contains the
  `ERROR:` line, the log path, `gpt-6-astra` (or the configured model) and
  the effort, and the hint naming `review.codex.model` and `--model`.
- With no model configured: the message says no model was passed, that the
  reviewer's default applies, and names `~/.codex/config.toml` for Codex and
  the CLI default for Claude.
- With a failure that has no `error` line, the last twenty lines of standard
  error appear; a long line is cut.
- The fake Claude is covered for the same output shape, including a failure
  reported in standard output.
- `.meta.json` has `model` and `effort` as passed and `model_source` for a
  flag, a config value and neither.
- The existing test that checks the rejected flag line still passes: its
  unrelated first stderr line is not printed because the cause lines are
  chosen by `error`.
- `node --test`, `npm run typecheck`, `npx @taprootio/trellis check` and
  `node scripts/good-agent.mjs check` are green.

## Notes

- Found 2026-11-02 by the GA0006 adoption in taproot; reported by the owner.
- Decision under work-task step 3: choose the cause lines by `error` match
  first and fall back to a tail, rather than always printing a tail. A
  Codex run prints progress and warnings that would bury the one error
  line in a plain tail.
- Decision: the detail is printed to standard error and not folded into the
  one-line meta `error`, so `.meta.json` stays small and stable for
  readers.
- Decision: the hint is keyed on the `model_not_found` code only. Other
  model failures print their own message through the cause lines.

## Risks

- A reviewer's output can echo parts of the prompt; the cause lines are
  chosen by `error` so the prompt is not printed, and each line is cut. The
  full output stays only in the `.log`, as now.
- A line containing `error` inside unrelated output (a file path such as
  `error.mjs`) can be selected. Bounded by the ten-line cap; accepted.

## Plan

1. A pure helper in `src/review.mjs` that takes the reviewer, its stdout and
   stderr, the model, the model source and the effort and returns the
   detail lines; the failure branch prints them after the `REVIEW_ERROR`
   line; `meta` gains `model_source`. Narrow check: the failure-mode and
   rejected-flag tests in `test/review.test.mjs` stay green. Commit.
2. Tests in `test/review.test.mjs` for each acceptance item using
   `test/fakes/codex` and `test/fakes/claude` (the fake Claude has
   `FAKE_RAW_STDOUT` but no `FAKE_STDERR`; add the same `FAKE_STDERR` the
   fake Codex has, written before the raw stdout line). Narrow check: `node
   --test test/review.test.mjs`. Commit.
3. Docs: `docs/review-runner.md`, `docs/design.md` section 12, the README
   review section, CHANGELOG. Narrow check: `node scripts/good-agent.mjs
   check`. Commit.
4. The diff review loop against the start commit (internal, then external),
   running the narrow checks after each fix. Then the gates once on the

   typecheck`, `node scripts/good-agent.mjs check`), rerun if a later change

   `completed/tasks/`, set `status: completed` and `completed_on`, write the
