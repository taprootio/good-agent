# GA0012 — Untrack the committed node_modules symlink and ignore the path, not only the directory

## Scope

Found 2026-11-02 while closing out GA0006. `git ls-files -s node_modules`
on `main` shows a mode `120000` entry: a symlink whose target is the
absolute path of the author's checkout. It arrived in PR #5 (`070aa9b`)
with a broad `git add`, because `.gitignore` had `node_modules/`, and a
trailing slash makes a pattern match directories only. A symlink is not a
directory to git, so it was not ignored. A clone sees a dangling link
until `npm ci` replaces it, and a checkout that already has the real
directory shows `D node_modules` forever.

- `git rm --cached node_modules`, so the link leaves the index without
  touching the working tree.
- `.gitignore`: `node_modules/` becomes `node_modules`, which matches the
  path whether it is a directory, a file or a symlink.
- A test in `test/release.test.mjs` that `node_modules` is not tracked and
  that the ignore file, applied in a scratch repository, ignores a
  `node_modules` symlink.

## Acceptance

- `git ls-files node_modules` prints nothing on the branch.
- `node --test` has a test that fails if either regression returns.
- `npx @taprootio/trellis check`, `node --test`, `npm run typecheck` and
  `node scripts/good-agent.mjs check` are green.

## Notes

- Deliberately not a release: nothing a consumer of the package observes
  changes. npm never packs `node_modules`, so the 0.2.0 and 0.3.0 tarballs
  are unaffected; the link is only in the git history and the tags. No
  changelog entry for the same reason.
- The tags `v0.2.0` and `v0.3.0` keep the link; rewriting them is not worth
  it.

## Risks

- None beyond the test's dependence on `git` being on the path, which the
  discovery tests already assume.

## Plan

1. Untrack the link, change the pattern, add the test. Narrow check:
   `node --test test/release.test.mjs`. Commit.
2. The four gates once, one external review round, close out, regenerate,
   commit.
